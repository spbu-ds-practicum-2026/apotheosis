# Сервис Feed: Feed DB на хеш-кольце, сессии, профили

Хеш-кольцо, `get_conn(key)`, схема Feed DB, ребалансировка, сессии, профили, Redis.

## Структура

```
deploy/docker-compose.yml        # (в корне репозитория) 3 узла PostgreSQL + Redis
services/feed/
├── feed/                        # Python-пакет сервиса
│   ├── db/
│   │   ├── ring.py              # хеш-кольцо: HashRing(nodes).get_node(key)
│   │   ├── connection.py        # конфигурация узлов, get_conn(key), node_for(key)
│   │   ├── rebalance.py         # перенос данных при смене состава узлов
│   │   └── schema.sql           # таблицы Feed DB (применяется к каждому узлу)
│   ├── auth.py                  # register, login, issue_session, verify_session, logout, ensure_profile
│   ├── profiles.py              # get_own_profile, get_public_profile, list_publications
│   └── cache.py                 # Redis: порции ленты, популярные пины
├── scripts/seed.py              # тестовые пользователи и пины
├── tests/
│   ├── unit/                    # без БД: кольцо, конфиг, auth, кэш
│   ├── e2e/                     # на настоящих узлах PostgreSQL
│   ├── conftest.py
│   └── pgwire.py                # тестовый клиент PostgreSQL, если нет psycopg
├── .env.example
├── pytest.ini
└── requirements.txt
```

## Запуск

```bash
docker compose -f deploy/docker-compose.yml up -d       # из корня репозитория
cd services/feed
pip install -r requirements.txt
cp .env.example .env && set -a && . ./.env && set +a
python -m scripts.seed          # 4 пользователя (seed_alice...), 30 пинов; пароль password123
pytest                          # тесты без БД
FEED_E2E=1 pytest               # + сквозные тесты на настоящих узлах
```

Импорты в коде сервиса: `from feed.db.connection import get_conn`, `from feed.auth import verify_session`.

## Как устроено шардирование

**Узел** = одна база PostgreSQL. Узлы стоят на хеш-кольце (по 256 токенов на узел, SHA-256).
Ключ принадлежит узлу, чей токен ближайший по часовой стрелке.

| Ключ | Таблицы |
|---|---|
| `userId` (логин) | `users`, `sessions`, `pin_requests`, `author_pins` |
| `pinId` (UUID) | `pins`, `interactions`, `outbox` |

Главное свойство кольца: при добавлении узла переезжает около 1/N ключей, и только на новый узел;
при удалении узла переезжают только его ключи. Состав узлов задаётся в окружении
(`FEED_NODES=N1,N2,N3`, `FEED_DSN_N1...`), а не в коде.

**Правила для всех, кто пишет в БД**
- Данные пользователя: `get_conn(user_id)`. Данные пина: `get_conn(pin_id)`. Другим ключом
  нельзя: строка окажется не на своём узле.
- Первичные ключи глобально уникальны (логин, UUID), автоинкрементов в схеме нет:
  строки переезжают между узлами. Новые таблицы делайте так же.
- Внешние ключи допустимы только внутри одной группы (все строки с одним ключом на одном узле).
- `pinId` кольцо приводит к нижнему регистру само, логин регистрозависим.

## Добавить или убрать узел

Запись в Feed на время переноса нужно остановить. Команды из `services/feed`.

```bash
docker compose -f ../../deploy/docker-compose.yml --profile scale up -d pg-node4   # новый узел со схемой
export FEED_DSN_N4=postgresql://feed:feed@localhost:5436/feed
python -m feed.db.rebalance --old N1,N2,N3 --new N1,N2,N3,N4 --dry-run   # посмотреть план
python -m feed.db.rebalance --old N1,N2,N3 --new N1,N2,N3,N4            # перенести
# FEED_NODES=N1,N2,N3,N4 и FEED_DSN_N4 во все инстансы Feed, перезапуск
python -m feed.db.rebalance --old N1,N2,N3,N4 --new N1,N2,N3,N4        # страховка: подберёт запоздавшее
```

Удаление узла: `--old N1,N2,N3,N4 --new N1,N2,N3`, узел должен быть доступен до конца.
Скрипт идемпотентен: после сбоя просто запустите заново. Строки удаляются с прежнего узла только
после того, как их полная копия найдена на новом. Подробный порядок: docstring в `feed/db/rebalance.py`.

## Что нужно знать остальным

**Проверка сессии** (замена заглушки «принимает любой токен»):

```python
from feed.auth import verify_session
user_id = verify_session(token)   # userId или None; на мусорный токен не падает
```

Токен: `<userId>.<случайная_строка>`. Логин: латиница, цифры, `_`, `-`, 3-32 символа
(точка запрещена, иначе токен не разобрать).

**Профили** возвращают словари, пригодные для JSON. Публикации листаются курсором:
`list_publications(user_id, limit, cursor)` → `{"items": [...], "next_cursor": ...}`.
`image_key` это ключ объекта в MinIO, presigned URL выдаёт Feed.

**Redis.** `Cache().get_json / set_json / invalidate_user`. Ключи `feed:<userId>:<порция>`
и `feed:popular`.

## Решения и отличия от ТЗ

- **Кольцо над узлами вместо 6 фиксированных логических шардов.** Так решила команда.
  Реплики, Patroni и etcd пока не подключены. Когда они появятся, на узел придётся
  реплика, а конфигурация кольца переедет из переменных окружения в etcd.
- **Пароли:** scrypt из стандартной библиотеки, а не argon2/bcrypt (ТЗ). Меняется
  в двух функциях `hash_password` / `verify_password`.
- **Токены в БД:** хранится SHA-256 случайной части, а не сам токен.
- **`password_hash` может быть NULL:** для входа через сторонний сервис.
  `ensure_profile(user_id)` создаёт профиль при первом входе, `issue_session(user_id)` выдаёт
  сессию. В ТЗ логин и пароль внутри Feed, в задачах Богдана сторонний сервис: поддержаны оба
  варианта, нужно согласовать.
- **Лайки в своём профиле** считаются обходом всех узлов (лайки лежат по `pinId`). Недоступный
  узел пропускается, тогда `likes_count_partial = true`.
- **`outbox` и `interactions`** это заготовка: формат согласовать с тем, кто делает лайки и
  отправку в брокер. `outbox` без автоинкремента (ключ `event_id`) и с `pin_id`, иначе
  строки нельзя переносить между узлами.
- **Ребалансировка не онлайн:** на время переноса запись нужно остановить.

## Как проверено

- Кольцо: 25 тестов (детерминизм, golden-раскладка, равномерность на 3-5 узлах, при добавлении
  узла ключи уходят только на него (~29%), при удалении только его ключи).
- Сквозные тесты на 4 настоящих узлах PostgreSQL 16: регистрация, занятый логин, гонка из
  6 потоков, истёкшая и чужая сессия, расположение строки на узле владельца, постраничный
  список публикаций, счётчик лайков по узлам.
- Ребалансировка: добавление 4-го узла и возврат. Сессии, профили, лайки, `outbox` (jsonb) и
  `pin_requests` остаются доступными, каждая строка лежит ровно на одном узле, повторный запуск
  ничего не находит. Перенос всей базы (275 ключей): итоговые счётчики таблиц не изменились,
  переехало 89 ключей.
- Не проверено: `docker compose`, `psycopg_pool` и `redis-py`. Они недоступны в окружении, где
  я писал код, поэтому сквозные тесты шли через встроенный клиент `tests/pgwire.py`, а кэш
  проверен на подменном Redis. Если psycopg установлен, `conftest.py` берёт его сам.
  CLI `rebalance` и `seed` используют psycopg, их запуск из командной строки не проверялся
  (функции внутри проверены).
- Тест ребалансировки нужен `FEED_DSN_N4` (пустая база со схемой) и без него пропускается.
